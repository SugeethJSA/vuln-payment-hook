This page demonstrates how the application grants access after the order transitions to PAID. Here is the security post-mortem of how the webhook exploit succeeded:

⚠️ Exploitation Flow (Insecure Mode)

1
Order Initialization: User clicks Checkout in Netflix. Server creates an order record in PENDING status.
2
Payment Bypass: Instead of executing a legitimate credit card transaction, the attacker skips the payment step.
3
Forged Webhook Dispatch: The attacker issues a POST /webhook/payment request containing {"order_id": "...", "payment_success": true}.
4
Unverified Processing: In Insecure Mode, the server accepts the payload without validating signatures or origin IP.
5
Unauthorized Access: Order state updates to PAID and unlocks full Netflix content for free!

🛡️ Mandatory Production Defense Checklist

  • 🔐 Cryptographic HMAC Signatures: Every inbound webhook must be signed using SHA-256 with a shared secret key (e.g. X-Webhook-Signature header).
  • 🌐 Gateway IP Whitelisting: Restrict webhook ingress strictly to official payment provider IP ranges (Stripe / Razorpay / PayU).
  • 🔁 Idempotency Keys & Replay Prevention: Record webhook event IDs to prevent replay attacks and duplicate processing.
  • 📞 Out-of-Band Status Verification: Query the payment provider's official REST API directly before modifying critical order state.
