Attack Vector — What Just Happened
1Order Created: The system generated a PENDING order without any payment commitment.
2Payment Skipped: No real money was transferred. The payment gateway was never contacted.
3Fake Webhook Sent: The /webhook/payment endpoint was called directly with a crafted payload.
4Blind Trust: The server accepted payment_success: true without any HMAC signature verification.
5Exploit Complete: Order status upgraded to PAID — premium content (worth ₹999+) unlocked for ₹0.
Mitigations — How to Prevent This
  • 🔐 HMAC Signature Verification: Compute and validate a shared-secret cryptographic digest on every inbound webhook payload before processing it.
  • 🌐 IP Allowlisting: Restrict the webhook endpoint to IP ranges published by the payment gateway provider. Reject all others.
  • 🔁 Idempotency Keys: Reject duplicate webhook events for the same order ID to prevent replay attacks.
  • 💰 Amount Validation: Cross-check the webhook-reported amount against the stored order amount before marking as paid.
  • 📞 Out-of-Band Confirmation: Query the payment gateway's REST API directly to verify transaction status — never rely solely on inbound webhooks.
  • ⏱ Timestamp / Replay Protection: Reject webhooks where the event timestamp is older than a configurable threshold (e.g., 5 minutes).
